# Instructions
<!-- Canonical project instructions for Claude Code, Codex, and GitHub Copilot. Edit this file only. -->

- Repo takes long-read sequencing cohorts from raw reads to annotated cohort VCFs - alignment, variant calling and callset integration, phasing, then annotation of SNVs/indels, SVs, MEIs, TRs and other complex variants - and was used to build the HPRC/HGSVC and All of Us callsets. Pipeline steps: [docs/pipeline.md](docs/pipeline.md); cohorts: [docs/cohort.md](docs/cohort.md).
- Stack: WDL 1.0 on Cromwell/Terra, Python 3.9+, Bash, Hail. GCP (`gs://` URIs). Reference genome GRCh38.
- Repo layout, Dockerfile/image conventions, and CI wiring: [docs/repository-structure.md](docs/repository-structure.md).
- WDL/Python style conventions: [docs/conventions.md](docs/conventions.md) — always follow when writing or editing WDL/Python. Match the dominant style of the surrounding file (4-space indent, no tabs, task section order `input` → `command` → `output` → `runtime`); never introduce a second style into a file.
- After changing any file under `wdl/`, run both of these and fix what they report before reporting the change complete:
  - Syntax: `find wdl -type f -name '*.wdl' -print0 | xargs -0 -n1 java -jar "${WOMTOOL_JAR:-womtool.jar}" validate`. Set `WOMTOOL_JAR` to a womtool 87 jar kept outside the repository, or fetch one into the worktree root with `curl -fsSL -o womtool.jar https://github.com/broadinstitute/cromwell/releases/download/87/womtool-87.jar`; it is gitignored (`*.jar`).
  - Style: `python .github/scripts/check_wdl_style.py` (checks `wdl/`; the same script runs in CI).
- Every workflow must document **every input and every output** in a `parameter_meta` block, in declaration order, plus a `meta { description: [...] }` block — `docs/workflows.md` is generated from these and must never be hand-edited. Rules: [docs/conventions.md](docs/conventions.md#workflow-documentation). Exceptions: never document `RuntimeAttr?`, `*_docker` or `prefix` inputs.
- After changing any file under `scripts/`, `.github/scripts/` or `tests/`, run `ruff check scripts .github/scripts tests`, `ruff format --check scripts .github/scripts tests` (config in `pyproject.toml`, line length 130) and `pytest tests/unit`, and fix what they report. Scripts in the Hail images must stay compatible with Python 3.9 (`hail`) and 3.6 (`vephail`); install the tooling with `pip install -e ".[dev]"`.
- After changing a workflow covered by `tests/wdl/`, or `dockerfiles/Dockerfile.utils`, run the WDL smoke tests: `dockerfiles/build_docker.sh --no-push utils`, then `MINIWDL__SCHEDULER__CONTAINER_BACKEND=podman UTILS_DOCKER=localhost/utils:<branch> pytest -m wdl tests/wdl`. Details: [tests/README.md](tests/README.md).
- After changing any workflow's `input` block, `docs/references.md` or `docs/dockers.md`, run `python .github/scripts/generate_example_inputs.py` to regenerate the example inputs in `inputs/`.
- After changing any `.md` file, run `python .github/scripts/check_markdown_style.py` (checks `README.md`, `AGENTS.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, the PR template, `docs/` and `tests/`; the same script runs in CI) and fix what it reports.
- Never develop directly on `main`, and never `git switch` in the main checkout — agents share it and it always stays on `main`. Start every change in its own worktree: `.github/scripts/new_worktree.sh <branch>` (any descriptive name other than `main`) cuts the branch from an up-to-date `origin/main`, pushes it, and prints the worktree path under `../lr-pipeline-worktrees/`. Run it with an existing branch name to resume that branch; it reuses that branch's worktree if one already exists, so pick a topic name not already in `git worktree list` unless resuming. Do every edit, command and check inside the printed path, and never touch another branch's worktree — repo hooks deny edits in the main checkout, refuse commits made there, and remind sessions there to run the script. The worktree shares the main checkout's local-only paths, listed in `.worktreelinks` (currently `data`), by symlink. Rules: [docs/conventions.md](docs/conventions.md#branches).
- When the branch changes a directly-run workflow — or a task library or `wdl/utils/` sub-workflow it imports — add the branch name under `filters.branches` in that workflow's `.dockstore.yml` entry, after `main`, so the branch version is importable into Terra. Only the workflows being tested get the branch; `main` stays listed in every entry.
- Never commit, push or merge to `main` on your own; the work waits, uncommitted, for review. Two instructions release it, and neither implies the other. "Commit" means commit the work in its worktree and push the branch, and nothing more. "Merge to `main`" means commit anything still outstanding, since the merge needs a clean worktree, and then merge.
- Bringing the branch up to date with `main` needs no instruction: `git fetch origin` and `git merge origin/main` inside the worktree, which keeps the pushed branch from ever needing a force push. Hand a conflict back rather than resolving it.
- To merge, run `.github/scripts/merge_branch.sh <branch>` from the main checkout, with the branch's worktree clean, and don't ask again — it strips the branch from `.dockstore.yml`, rebases in the branch's worktree, fast-forwards `main` in the main checkout, pushes, then removes the worktree, deletes the branch and deletes the branch's image tags. Merge locally; don't open a pull request - that is the maintainer workflow, and external contributors use a fork and a pull request per [CONTRIBUTING.md](CONTRIBUTING.md). Afterwards `cd` back to the main checkout, since the worktree path is gone, and rebuild from there any image the branch built, so the dated tag and `:latest` carry the merged change. Details: [docs/ci-cd.md](docs/ci-cd.md#feature-branch-test-versions).
- Leave the work uncommitted when handing a task back, so the editor still marks the changed lines for review. End the handover with every file changed, one per line, each a Markdown link — target the path relative to the editor's workspace root when it is known, otherwise the absolute path — followed by a few words on what changed in it.
- Stop and hand back if the script reports a rebase conflict, leaving the rebase in progress. Conflicts are the one thing to surface for review; never resolve them automatically.
- New directly-run workflows need a `.dockstore.yml` entry — match the format of existing entries.
- New annotation/tool checklist: implement in `wdl/`, adding to `scripts/` only if inline Python in the workflow isn't enough → add/update Dockerfile if new deps needed → register in `.dockstore.yml` → write `meta` and `parameter_meta` covering every input and output → update any other affected `docs/`.
- `archive/` contains retired workflows, scripts, Dockerfiles, and reference documentation. It is not active pipeline code and is excluded from the style checks and Dockstore registration; do not use it for new work. Its workflows import the active task libraries and are womtool-validated against them, so after changing a file under `wdl/utils/` also run `find archive/wdl -type f -name '*.wdl' | grep -vxFf archive/wdl/womtool-excluded.txt | xargs -n1 java -jar "${WOMTOOL_JAR:-womtool.jar}" validate` and fix the archived call sites it reports - see [docs/ci-cd.md](docs/ci-cd.md#archived-workflows). Its workflows still carry `meta` and `parameter_meta` blocks, which generate `archive/docs/workflows.md` via `python .github/scripts/generate_workflows_doc.py --site archive`; never hand-edit that document either.
- After changing a file under `scripts/`, rebuild the `utils`, `hail` and `vephail` images from `main` once merged, since scripts are baked in at `/opt/scripts` and never fetched by URL - see [docs/repository-structure.md](docs/repository-structure.md#scripts).
- Don't hardcode Docker image URIs in WDL — always pass as a `String` input.
- Build images only with `dockerfiles/build_docker.sh <image-name>`, run from the branch's worktree: on a branch it pushes `<image>:<branch>` only and never moves `:latest`, so point that branch's Terra method config at the branch tag. The `<YYYYMMDD>-<short-sha>` tag and `:latest` come only from a build on `main` in the main checkout, which refuses a dirty tree. `--no-push` builds locally without pushing. Rules: [docs/dockers.md](docs/dockers.md#building-and-pushing).
